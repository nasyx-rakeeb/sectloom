# Sectloom Registry

The Sectloom Registry is the canonical distribution channel for production-ready React TSX sections. It conceptually aligns with the Shadcn/UI registry standard but extends it with strict Zod-enforced contracts, specific component metadata, Next.js range tracking, and cryptographic integrity hashes.

## Registry Output

The registry exposes deterministic JSON artifacts generated by `packages/registry`. These artifacts include:

- `index.json`: A lightweight directory of all available components, containing category, description, and dependency summaries.
- `[name].json`: Detailed individual registry entries including the complete inline TSX source code, configuration requirements, and deterministic checksums.

## Versioning & Release Workflow

Sectloom employs a dual-versioning approach:

1. **Package Versioning:** The `@sectloom/registry` and `@sectloom/components` packages are versioned according to standard SemVer conventions.
2. **Component Versioning:** Individual components (e.g., `hero-efficiency`) maintain their own internal version field (currently `0.1.0`). In the future, breaking changes to a specific component will increment its version, ensuring older consumers can fetch backward-compatible iterations from the CDN using `v1` vs `v2` endpoints.

### Release Workflow

1. **Develop Component:** Build and validate the new section within `packages/components`.
2. **Metadata Registration:** Register the component in `packages/registry/src/metadata.ts`, ensuring all documentation and Next.js compatibility ranges are accurate.
3. **Build & Hash:** Run `pnpm run build` in the registry package. The system deterministically parses, sorts, and hashes the component code to generate strict SHA-256 integrity checks.
4. **Validation:** The resulting output is checked against `@sectloom/contracts/src/registry.ts`.
5. **Deployment:** The generated `public/` folder is deployed to an immutable global edge CDN.

## Integrity Verification

Every file processed by the registry emits a `checksum` using SHA-256. The overarching component JSON also computes a hash of its internal properties. The future Sectloom CLI will automatically generate matching hashes upon code download to guarantee against MITM attacks or partial file corruption.
